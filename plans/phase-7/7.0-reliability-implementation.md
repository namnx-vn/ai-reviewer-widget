# Phase 7 — Reliability Implementation Contract

Status: Implementation complete for this reliability foundation; empirical production qualification remains blocked.

This implements the authorized sequence: adjudication → holdout and precision/recall gates → claim-bound verification → full-repository/PR evaluation → durable learning and controlled promotion. It does not claim the twenty-phase end-state roadmap or universal review quality is complete.

## 1. Establish trustworthy observations

- Preserve `evaluation/real-world/phase-6.11-observations.json` byte-for-byte.
- Audit all seven pending findings against fixture behavior and pinned upstream source, documenting provenance and contradictory minimization.
- Publish a new observation with reviewed, pending, excluded and eligible denominators. Invalid fixture fidelity cannot qualify empirical correctness.
- Keep genuine misses visible; do not add evaluation mappings without matching bug semantics.

Verify: adjudication and observation tests, a fresh production corpus replay, and comparison with the immutable frozen artifact.

## 2. Isolate holdout and enforce measurable quality

- Validate versioned development/calibration/holdout manifests, unique case identities, repository isolation, temporal cutoffs and candidate exposure.
- Preserve the existing corpus as development evidence because its findings are already inspected. New unseen protected evidence requires separate provenance.
- Require raw finding precision and a conservative Wilson lower bound for the proportion of clean repository units separately. The repository-unit bound is not a finding-precision confidence interval; many findings from one repository cannot inflate its effective sample count.
- Enforce explicit sample minima, precision qualification, recall floors, paired protected-positive/negative-control preservation, critical false-positive rejection and complete verdict coverage.
- Operational success and finding correctness are distinct results. Missing samples return `insufficient-evidence`; measured failures remain failures.

Verify: leakage, malformed policy/data, small samples, suppression-induced recall loss, protected negative regressions and passing paired candidates.

## 3. Bind AI conclusions to evidence

- Require a structured claim identifying canonical deterministic evidence, exact source location and matching rule/finding identity.
- Another issue in the same file or nearby line is not support.
- A supported AI conclusion uses the canonical detector conclusion; naming a real detector cannot launder invented severity, message or suggestion.
- Never increase confidence from raw model self-confidence or deterministic detector certainty. Unverified claims remain non-blocking advisory observations.
- Preserve existing parser validation, module boundaries and deterministic outputs.

Verify: unrelated SQL/React claim, invented high-confidence critical claims, missing location, malformed claims, canonical support, provider parsing and engine decisions.

## 4. Evaluate full repositories and PR changes

- Run complete offline repository manifests through `ReviewUseCases`; separately identify minimized, synthetic and source-backed evidence.
- Run both base and head, compare introduced/worsened/resolved/baseline findings, and check incremental/full-analysis parity.
- Exercise multi-package and cross-file context, security and React examples, and optional injected AI through the same production pipeline.
- Report missing paths, unsupported input, parse warnings and context budgets explicitly. Incomplete runs cannot become clean passes or gate evidence.
- Provide a local operator entry point for complete repository and PR manifests, with machine-readable artifacts and nonzero exit on failed qualification.

Verify: real composition-root integration tests, adversarial AI, incomplete context and parity regressions. Synthetic snapshots are engineering tests, not new empirical holdout repositories.

## 5. Persist learning and govern promotion

- Record metadata for every operated review, including zero findings; store verified outcomes and explicitly reported missed bugs.
- Durable infrastructure storage stays outside application code. Reload validates schema and preserves immutable event/artifact lineage.
- Repeated accepted/fixed actions are one finding outcome; conflicting or untrusted labels cannot become ground truth without adjudication.
- Mine reproducible, repository-scoped failure clusters with references and sample counts. Proposals and regression fixtures remain pending until verified.
- Candidate evaluation and shadow are isolated from visible GitHub findings; generated code/source instructions are data and never executed.
- Require verified regression coverage, protected evaluation, bounded shadow evidence and an explicit authorization before promotion.
- Bind receipts to candidate artifact, baseline and dataset/policy versions. Reject stale/mismatched receipts, mandatory-control weakening and concurrent promotion conflicts. Retain auditable rollback.

Verify: durable reload/corruption, dedup/conflicts, zero-finding misses, immutable candidate lineage, insufficient evidence, swapped receipts, shadow isolation, promotion and rollback.

## Remaining empirical and operational limits

- Reconstruct the two quarantined captures faithfully, retain their audit trail, and grow independently verified unseen repository cohorts. Existing inspected fixtures remain development evidence.
- Measure actual calibration, actionability, critical recall, provider variation and real traffic drift before claiming the roadmap's 95%/98% targets.
- Source/adjudication file imports are explicitly human-audited execution evidence; metadata integrity checks alone do not execute/prove candidate behavior or establish complete upstream inventory.
- The approved operator policy is immutable and prevents bundle-defined weaker floors. Trusted callers may compose a different versioned policy through the application ports; that is an engineering configuration action.
- Shadow helper input caps, elapsed deadline rejection and cooperative cancellation do not provide hard CPU/memory preemption. It reports `hardResourceIsolation: false`; dedicated process isolation remains required before automatic production traffic shadowing.
- Promotion changes the approved artifact journal, with actual code deployment left to the normal engineering workflow. Normal existing CLI/GitHub entry points are not silently switched to online learning.

No live rule/prompt/model training or automatic source modification is authorized by this contract. Operational details: [Continuous Review Intelligence](../../docs/review-intelligence.md).
