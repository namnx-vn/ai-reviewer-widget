# Phase 6.6 — Production GitHub Review Workflow

Status: ✅ Complete

## Objective

Make repeated PR reviews behave like a maintained review product rather than a one-shot publisher that creates duplicate comments on every push.

## Implemented Lifecycle

```text
First review
  ↓
publish finding with stable hidden fingerprint marker

Next push
  ↓
reconcile existing review comments
  ├── same fingerprint → preserve
  ├── new fingerprint → create
  └── missing fingerprint → mark Resolved
```

GitHub publication consumes the shared application `ReviewResult`; analysis results remain authoritative and are never mutated by publication failure.

## Publication Safety

- stable comment identity derives from the shared Phase 6.5 finding fingerprint
- repeated pushes do not create duplicate inline comments
- stale comments receive explicit `Resolved` lifecycle state
- bounded publication retry defaults to two attempts and cannot exceed three
- partial publication failure propagates as an observable error without changing analysis/scoring
- Check Run annotations are capped at GitHub's 50-annotation request limit and omitted count is reported deterministically
- Check Run summary remains deterministic
- updated semantic findings are represented by resolve + create when their stable fingerprint changes; non-semantic line movement preserves identity

SARIF remains an independent CI publication surface; GitHub PR lifecycle reconciliation does not duplicate application review logic into a SARIF-specific analysis path.
