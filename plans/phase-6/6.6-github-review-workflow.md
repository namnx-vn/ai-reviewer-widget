# Phase 6.6 — Production GitHub Review Workflow

Status: ⏳ Planned

## Objective

Make repeated PR reviews behave like a maintained review product rather than a one-shot publisher that creates duplicate comments on every push.

## Scope

Improve lifecycle handling for:

- Check Runs
- PR comments
- annotations
- SARIF publication
- previous review output
- stale/resolved findings
- updated findings
- bounded retry and publication failures

## Desired Lifecycle

```text
First review
  ↓
publish finding

Next push
  ↓
match by stable identity
  ├── still present → preserve/update
  └── gone → mark resolved/stale according to policy
```

## Publication Boundary

Analysis results remain authoritative. GitHub publication failures must never mutate `ReviewResult` or change analyzer/scoring decisions.

## Acceptance Criteria

- [ ] stable GitHub finding identity maps from shared finding identity
- [ ] repeated pushes do not create duplicate comments
- [ ] changed findings can update existing output
- [ ] resolved findings have explicit lifecycle behavior
- [ ] Check Run summary remains deterministic
- [ ] GitHub annotation limits are handled explicitly
- [ ] publication failures are observable and non-corrupting
- [ ] retry behavior is bounded
- [ ] GitHub continues to consume shared application review results
- [ ] tests cover repeated pushes to one PR
- [ ] tests cover partial publication failure
- [ ] stale output handling is documented
