# Phase 6.8 — AI Context Selection & Verification

Status: ✅ Complete

## Objective

Improve AI usefulness by sending bounded repository-relevant context and by applying evidence-aware confidence behavior to AI findings.

## Context Selection

```text
PR Change
   ↓
Repository Context
   ↓
Relevant Symbols / Modules
   ↓
Bounded AI Context
   ↓
AI Review
```

Do not send the entire repository by default.

## Explicit Budgets

Context selection supports deterministic limits for:

- maximum files
- maximum characters
- maximum dependency depth
- maximum related symbols

Provider-specific token accounting may refine, but not replace, deterministic selection.

## Finding Verification

Where deterministic evidence is available:

```text
AI Finding
   ↓
Evidence Resolver
   ├── supported → preserve/raise confidence according to policy
   ├── unsupported → reduce confidence according to policy
   └── unverifiable → preserve capability-aware behavior
```

Verification remains capability-aware because not every architectural observation is deterministically provable.

## Constraints

- Existing input-policy/sanitization applies after context selection.
- Specialist agents remain bounded by concern and context.
- Verification failure must not crash deterministic review.
- AI does not gain direct filesystem or repository adapter access.

## Implementation Notes

- `src/ai/context-selector.ts` provides deterministic repository-aware context selection with explicit file, character, dependency-depth, and related-symbol budgets.
- Selection is performed before the existing outbound input policy so secret redaction and truncation remain the final safety boundary.
- `src/ai/verification.ts` applies evidence-aware verification without mutating deterministic findings or giving AI providers repository access.
- AI finding evidence can retain provenance to selected repository files and deterministic findings.
- Unsupported evidence follows an explicit confidence-reduction policy; unverifiable observations remain capability-aware rather than being falsely rejected.
- Verification failures degrade safely and preserve deterministic review output.
- Tests cover bounded relevant selection, unrelated-file exclusion, selected-context sensitive-data handling, evidence confidence behavior, and safe fallback.
