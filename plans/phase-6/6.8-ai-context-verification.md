# Phase 6.8 — AI Context Selection & Verification

Status: ⏳ Planned

## Objective

Improve AI usefulness by sending bounded repository-relevant context and by applying evidence-aware confidence behavior to AI findings.

## Context Selection

```text
PR Change
   ↓
Repository Context
   ↓
Relevant Symbols / Modules
   ↓
Bounded AI Context
   ↓
AI Review
```

Do not send the entire repository by default.

## Explicit Budgets

Context selection should support deterministic limits such as:

- maximum files
- maximum characters/tokens
- maximum dependency depth
- maximum related symbols

Provider-specific token accounting may refine, but not replace, deterministic selection.

## Finding Verification

Where deterministic evidence is available:

```text
AI Finding
   ↓
Evidence Resolver
   ├── supported → preserve/raise confidence according to policy
   └── unsupported → reduce confidence or filter according to policy
```

Verification must be capability-aware because not every architectural observation is deterministically provable.

## Constraints

- Existing input-policy/sanitization applies after context selection.
- Specialist agents remain bounded by concern and context.
- Verification failure must not crash deterministic review.
- AI does not gain direct filesystem or repository adapter access.

## Acceptance Criteria

- [ ] typed AI context selector contract exists
- [ ] context selection uses repository context
- [ ] context budgets are explicit
- [ ] unrelated files are excluded by deterministic tests
- [ ] secret/input sanitization still applies
- [ ] specialist prompts receive bounded relevant context
- [ ] evidence provenance can attach to AI findings
- [ ] unsupported evidence follows explicit confidence policy
- [ ] verification failures degrade safely
- [ ] sensitive-data tests cover selected context
- [ ] default single-agent behavior remains backward compatible unless explicitly configured
