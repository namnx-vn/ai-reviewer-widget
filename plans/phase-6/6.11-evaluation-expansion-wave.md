# Phase 6.11 — Evaluation Expansion Wave

Status: ✅ Complete

## Objective

Stress-test precision and generalization by expanding the adjudicated public-PR denominator before adding or tuning production rules.

## Baseline

- 50 executable public-PR cases
- 17 manually adjudicated `must-find` expectations, all detected through exact production-rule mappings
- 5 empirical `must-not-find` controls, of which 3 are in the narrower `clean-negative` category
- 29 emitted production findings
- precision pending because incidental findings are not automatically true or false positives

## Scope

1. Promote 25 faithful TypeScript/TSX cases to reach a 75-PR executable corpus.
2. Add positive expectations before considering new rule work.
3. Raise the empirical `must-not-find` denominator from 5 to at least 15.
4. Report baseline and expansion-wave TP/FN separately. An unmapped `must-find` expectation is a false negative, not missing data.
5. Introduce an auditable finding-adjudication manifest. Precision remains unavailable until every emitted finding has a verdict.

The `empiricalNegativeControls` metric is the target denominator for this wave. `empiricalCleanControls` remains the narrower subset whose case category is `clean-negative`.

## Constraints

- Do not add or tune production rules in this wave.
- Do not use PR numbers, fixture ids, or evaluation-only paths in production analysis.
- Promote only source-backed TypeScript/TSX behavior. Rust-only changes remain catalogued.
- Preserve exact public repository, PR URL, head SHA, upstream-like analysis path, expectation, and rationale.
- Treat incidental findings as pending until explicitly adjudicated.
- Keep the existing 50 cases in a frozen `baseline-50` cohort and new cases in `expansion-wave-1`.

## Acceptance Criteria

- [x] executable corpus contains 75 unique public PRs
- [x] expansion cohort contains 25 cases and at least one new positive expectation
- [x] empirical `must-not-find` controls are at least 15
- [x] observation schema reports aggregate and per-cohort TP/FN
- [x] all unmapped new positive expectations appear as false negatives
- [x] the 17 baseline semantic findings have auditable true-positive adjudications
- [x] the remaining emitted findings stay explicitly pending until reviewed
- [x] precision status distinguishes pending, partial, and measured adjudication
- [x] no production rule changes are included
- [x] typecheck, lint, evaluation tests, full tests, and build pass
