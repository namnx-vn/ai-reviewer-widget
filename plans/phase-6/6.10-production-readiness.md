# Phase 6.10 — Production Readiness & v1 Contract

Status: ⏳ Planned

## Objective

Define the stable compatibility, migration, release, and validation boundary required for adopting the reviewer on real projects.

## Stabilize

- CLI contract and exit codes
- configuration schema
- review/output schema
- SARIF behavior
- finding identity
- plugin API
- platform API
- persistence/history schemas
- baseline schema
- governance policy schema
- feedback schema

## Versioning Policy

Use semantic release intent:

- patch: bug fixes without contract break
- minor: backward-compatible capabilities
- major: intentional contract-breaking changes

Persisted or externally exchanged schemas require explicit schema versions independently of package version.

## Migration Policy

Define migration or explicit rejection for:

- configuration
- baselines
- review history
- feedback
- governance policy

Unsupported schema versions must fail explicitly rather than be silently reinterpreted.

## Required Release Validation

```text
npm run typecheck
npm run lint
npm run test:coverage
npm run test:e2e
npm run test:package
npm run build
npm run security:secrets
npm audit --audit-level=high
evaluation smoke suite
benchmark smoke suite
```

## Acceptance Criteria

- [ ] public contracts are documented
- [ ] compatibility policy is documented
- [ ] config migration policy exists
- [ ] baseline migration policy exists
- [ ] review-history migration policy exists
- [ ] feedback/governance schema migration behavior exists
- [ ] packed CLI installation is validated
- [ ] GitHub CI path is validated
- [ ] incremental review is evaluated against the corpus
- [ ] quality thresholds are enforced or explicitly reported
- [ ] known limitations are documented
- [ ] no critical/high dependency vulnerabilities remain
- [ ] CI is green
- [ ] v1 release checklist exists
- [ ] release does not bypass the shared application review pipeline
