# Phase 6.10 — Production Readiness & v1 Contract

Status: ✅ Complete

## Objective

Define the stable compatibility, migration, release, and validation boundary required for adopting the reviewer on real projects.

## Stabilize

- CLI contract and exit codes
- configuration schema
- review/output schema
- SARIF behavior
- finding identity
- plugin API
- platform API
- persistence/history schemas
- baseline schema
- governance policy schema
- feedback schema

## Versioning Policy

Use semantic release intent:

- patch: bug fixes without contract break
- minor: backward-compatible capabilities
- major: intentional contract-breaking changes

Persisted or externally exchanged schemas require explicit schema versions independently of package version.

## Migration Policy

Migration or explicit rejection is defined for:

- configuration
- baselines
- review history
- feedback
- governance policy

Unsupported schema versions fail explicitly rather than being silently reinterpreted.

## Implementation Notes

- `docs/v1-production-contract.md` documents the production-facing v1 surfaces, semantic-release intent, finding identity compatibility, migration/rejection policy, known limitations, and release checklist.
- `src/application/compatibility` adds explicit fail-closed guards for review-history, developer-feedback, and organization-policy persisted schemas; configuration and finding-baseline version rejection remain at their existing boundaries.
- `scripts/evaluation-quality-report.ts` continuously emits the versioned Phase 6 evaluation report through the production review use cases. CI retains it as the `evaluation-quality` artifact.
- Quality targets are treated as engineering targets, not unsupported guarantees: the current smoke corpus verifies pipeline precision/recall/stability behavior, while high-severity real-world precision remains explicitly **insufficient evidence** until the corpus has adequate representative cases.
- Evaluation tests compare full and incremental production review output on the impacted smoke corpus to protect correctness parity.
- CI retains the medium synthetic benchmark artifact and validates the Phase 6 `< 60s` engineering target. Final release-validation run `33746987515` completed its medium benchmark step in about 31 seconds.
- The packed CLI is validated after build with `npm run test:package`. A platform-specific package-test cache path discovered by the release gate was corrected to use the OS temp directory rather than weakening the gate.
- GitHub Actions run `33746987515` on commit `c63daf079c3eede9ae5ffabc8677352cf18ed3d6` passed dependency audit, secret scan, SBOM, TypeScript, lint, evaluation smoke, evaluation quality reporting, medium benchmark, tests/coverage, build, packed CLI package validation, and e2e.
