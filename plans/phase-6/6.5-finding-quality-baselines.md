# Phase 6.5 — Finding Quality, Suppression & Baselines

Status: ⏳ Planned

## Objective

Keep established projects usable by distinguishing new regressions from known findings and by giving findings stable identity beyond raw line numbers.

## Scope

Introduce:

- stable finding fingerprint
- lifecycle state
- baseline comparison
- suppression
- accepted-risk state
- regression detection
- resolved finding detection
- duplicate/history correlation

## Finding Lifecycle

```text
new
existing
suppressed
accepted
resolved
regressed
```

Lifecycle must remain separate from severity.

## Stable Identity

Fingerprinting should consider rule ID, repository-relative path, semantic/symbol context, location class, and relevant evidence. Ordinary line movement must not automatically create a new finding identity.

## Suppression

Start with explicit configuration-based suppression containing rule, scope, and reason. Inline source-code suppression is deferred until syntax and governance implications are explicitly designed.

## Acceptance Criteria

- [ ] stable finding fingerprint contract exists
- [ ] baseline schema is versioned
- [ ] new vs existing findings are distinguishable
- [ ] resolved findings are detectable
- [ ] regressions are detectable
- [ ] suppressions include rule, scope, and reason
- [ ] suppression behavior is deterministic
- [ ] mandatory governance/security controls cannot be silently weakened
- [ ] ordinary line shifts preserve identity where semantic context is unchanged
- [ ] supported rename/move behavior is covered
- [ ] baseline compatibility/migration behavior is tested
- [ ] lifecycle state does not overload severity
