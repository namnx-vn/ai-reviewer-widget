# Phase 6.5 — Finding Quality, Suppression & Baselines

Status: ✅ Complete

## Objective

Keep established projects usable by distinguishing new regressions from known findings and by giving findings stable identity beyond raw line numbers.

## Scope

Implemented:

- stable finding fingerprint
- lifecycle state
- versioned baseline comparison
- configuration-based suppression
- accepted-risk state
- regression detection
- resolved finding detection
- deterministic identity/history correlation

## Finding Lifecycle

```text
new
existing
suppressed
accepted
resolved
regressed
```

Lifecycle remains separate from severity.

## Stable Identity

Fingerprinting uses rule ID, normalized repository-relative path, semantic context, location class, and relevant evidence. Raw line numbers are deliberately excluded, so ordinary line movement does not create a new identity. Supported rename/move correlation uses explicit path aliases.

## Suppression

The existing versioned review configuration now supports explicit finding suppressions containing rule, scope, and reason. Configuration validation is fail-closed for incomplete suppressions and unknown rules. Mandatory rule IDs can be protected from suppression by lifecycle policy.

Inline source-code suppression remains deferred.
