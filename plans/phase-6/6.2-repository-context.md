# Phase 6.2 — Repository Context Intelligence

Status: ✅ Complete

## Objective

Allow analyzers to reason safely across files, modules, packages, and framework configuration without duplicating repository discovery logic inside rules.

## Scope

Introduce a shared immutable repository context containing:

- source-file index
- module/import graph
- export and re-export index
- declaration index
- conservative cross-file symbol relationships
- package/workspace boundaries
- `tsconfig` awareness
- `package.json` awareness
- framework/project signals

## Architecture

```text
Repository Sources
      ↓
Repository Indexer
      ↓
RepositoryContext
 ├── files
 ├── imports
 ├── exports
 ├── declarations
 ├── packages
 └── project metadata
      ↓
Deterministic Analyzers
```

## Initial Resolution Support

- relative imports and index files
- deterministic TypeScript path aliases
- package-local imports
- named/default exports
- re-exports and `export *`
- common function/class/variable/component/hook declarations
- circular dependency representation without recursive failure

## Constraints

- Do not implement a replacement TypeScript compiler.
- Rules consume context; rules must not independently walk the filesystem.
- Repository context must not be a mutable global singleton.
- Existing single-file analysis paths must remain compatible while migration is incremental.

## Implementation Notes

- `src/analyzer/repository-context/` owns the shared repository context contract and deterministic indexer.
- The deterministic analyzer adapter constructs one context per analysis and supplies it as an optional contribution argument, preserving existing contribution implementations.
- Resolution supports relative/index files, named/default/star re-exports, conservative TypeScript path aliases, and workspace package-local imports.
- Package and project metadata are derived only from repository inputs; rules do not read the filesystem or process environment independently.
- Circular and unresolved relationships fail soft through bounded visited-state resolution and `undefined` results.
- Barrel, circular, alias, multi-package, unresolved-import, and analyzer-composition behavior are covered by tests.
- Completion was validated by GitHub Actions with typecheck, lint, evaluation smoke tests, full tests/coverage, build, and e2e all passing.
