# Phase 6.2 — Repository Context Intelligence

Status: ⏳ Planned

## Objective

Allow analyzers to reason safely across files, modules, packages, and framework configuration without duplicating repository discovery logic inside rules.

## Scope

Introduce a shared immutable repository context containing:

- source-file index
- module/import graph
- export and re-export index
- declaration index
- conservative cross-file symbol relationships
- package/workspace boundaries
- `tsconfig` awareness
- `package.json` awareness
- framework/project signals

## Architecture

```text
Repository Sources
      ↓
Repository Indexer
      ↓
RepositoryContext
 ├── files
 ├── imports
 ├── exports
 ├── declarations
 ├── packages
 └── project metadata
      ↓
Deterministic Analyzers
```

## Initial Resolution Support

- relative imports and index files
- deterministic TypeScript path aliases
- package-local imports
- named/default exports
- re-exports and `export *`
- common function/class/variable/component/hook declarations
- circular dependency representation without recursive failure

## Constraints

- Do not implement a replacement TypeScript compiler.
- Rules consume context; rules must not independently walk the filesystem.
- Repository context must not be a mutable global singleton.
- Existing single-file analysis paths must remain compatible while migration is incremental.

## Acceptance Criteria

- [ ] repository context contract exists
- [ ] index construction is deterministic
- [ ] supported JS/TS imports are represented
- [ ] export and re-export relationships are indexed
- [ ] basic cross-file declaration resolution works
- [ ] package boundaries are represented
- [ ] `tsconfig` path aliases are handled conservatively
- [ ] unresolved imports degrade safely
- [ ] circular imports do not crash indexing
- [ ] barrel exports are tested
- [ ] multi-package repositories are tested
- [ ] existing analyzers remain compatible
- [ ] R1 dependency boundaries remain green
