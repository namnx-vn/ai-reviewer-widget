# Phase 6.4 — Incremental PR Analysis

Status: ✅ Complete

## Objective

Make pull-request review fast enough for continuous use by analyzing changed scope plus required dependency impact instead of blindly rescanning everything.

## Scope

Implemented reusable analyzer-level representation for:

- changed files
- changed ranges
- changed symbols
- direct and transitive dependents
- impacted modules/packages
- relevant import/export relationships
- rules that still require repository-wide execution
- deleted and renamed files
- deterministic runtime/scope metrics

## Rule Execution Scope

The backward-compatible execution-scope contract is:

```ts
type RuleExecutionScope =
  | "changed-range"
  | "changed-file"
  | "affected-module"
  | "repository";
```

Existing contributions default safely to `repository`. Contributions opt into narrower execution only when they explicitly declare a narrower scope.

## Safety Requirement

Incremental execution never silently narrows an existing contribution whose correctness may require repository-wide analysis. Full repository review remains available for audits and baseline creation.

The change model belongs to the analyzer/application boundary and contains no GitHub-specific concepts, so CLI, CI, GitHub, and future adapters can reuse it.
