# Phase 6.4 — Incremental PR Analysis

Status: ⏳ Planned

## Objective

Make pull-request review fast enough for continuous use by analyzing changed scope plus required dependency impact instead of blindly rescanning everything.

## Scope

Determine and represent:

- changed files
- changed ranges
- changed symbols
- direct dependents
- impacted modules/packages
- relevant import/export relationships
- rules that still require repository-wide execution

## Rule Execution Scope

Introduce a backward-compatible execution-scope contract:

```ts
type RuleExecutionScope =
  | "changed-range"
  | "changed-file"
  | "affected-module"
  | "repository";
```

Existing rules receive a safe default and migrate incrementally.

## Safety Requirement

Incremental execution must never silently skip a rule whose correctness requires repository-wide analysis. Full repository review remains available for audits and baseline creation.

## Acceptance Criteria

- [ ] changed-file scope is reusable outside GitHub
- [ ] changed line/range information is represented
- [ ] impacted-module calculation exists
- [ ] rule execution-scope contract exists
- [ ] existing rules have safe backward-compatible defaults
- [ ] repository-scoped rules remain repository-scoped
- [ ] incremental findings match full-review findings for impacted deterministic fixtures
- [ ] deleted files are covered
- [ ] renamed files are covered
- [ ] changed exports and shared dependencies are covered
- [ ] runtime/stage metrics are recorded
- [ ] no GitHub-specific concept leaks into analyzer/domain contracts
