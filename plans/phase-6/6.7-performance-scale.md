# Phase 6.7 — Performance & Scale

Status: ⏳ Planned

## Objective

Validate and improve reviewer performance on realistic repository sizes without sacrificing correctness or determinism.

## Benchmark Classes

- small: < 10k LOC
- medium: 10k–50k LOC
- large: 50k–100k+ LOC

These are benchmark categories, not product limits.

## Measure

- total review duration
- repository indexing duration
- parse duration
- deterministic analysis duration
- AI duration
- peak memory
- files/symbols/rules processed
- full vs incremental duration
- cache hit ratio when caching exists

## Optimization Candidates

Only after measurement justifies them:

- parsed AST cache
- repository-index cache
- incremental graph updates
- memoized module resolution
- bounded worker concurrency
- bounded AI concurrency
- lazy analyzers/adapters

## Constraints

- No cache may change findings.
- Do not introduce workers or persistent caching without benchmark evidence.
- Performance optimizations must preserve deterministic output.

## Acceptance Criteria

- [ ] reproducible benchmark command exists
- [ ] benchmark result contract exists
- [ ] controlled small/medium/large benchmark datasets exist
- [ ] peak memory is measured
- [ ] stage durations are measured
- [ ] incremental vs full review can be compared
- [ ] performance regressions can be detected
- [ ] cache behavior is deterministic if introduced
- [ ] cache invalidation has correctness tests if introduced
- [ ] medium-repository target is measured against Phase 6 goals
- [ ] benchmark tooling is separate from production review logic
