# Phase 3.4.6 — React Performance Intelligence

> Engineering contract: [`../../../AGENTS.md`](../../../AGENTS.md)

Status: ✅ Complete

---

## Objective

Detect React-specific performance risks using static semantic analysis.

---

## Areas

- expensive render work
- expensive computations
- large list rendering
- unnecessary memoization
- inefficient derived values
- avoidable render-time work

---

## Implemented Rules

### `react.performance.expensive-render-work`

Detect statically evident collection work on dynamic component inputs when it runs directly during render:

- `sort()` / `toSorted()` on render-time collections
- three or more collection passes in a single derived expression

The rule ignores work isolated behind a nested callback such as `useMemo`.

### `react.performance.unbounded-list-render`

Detect JSX produced by mapping an entire dynamic collection when no static render bound is visible.

False-positive protection includes accepting an explicit bounded prefix such as `slice(0, 50)`.

The finding is reported as a scaling risk, not as proof that the current list is large.

### `react.performance.trivial-use-memo`

Detect `useMemo` around trivial expressions that contain no calls, allocations, or collection traversal.

Object/array creation is intentionally excluded because stable identity can be semantically useful.

### `react.performance.repeated-derived-computation`

Detect structurally identical dynamic collection derivations repeated in the same render path.

Only exact normalized source matches are reported to keep confidence high.

### `react.performance.render-time-construction`

Detect avoidable formatter/regular-expression construction directly during render:

- `Intl.*` formatter constructors
- literal-configured `new RegExp(...)`

Dynamic `RegExp` construction is ignored because static evidence is insufficient.

---

## Requirements

Performance rules must avoid claiming runtime performance problems when static evidence is insufficient.

Confidence must reflect analysis certainty.

False-positive protection is mandatory.

---

## Validation Coverage

Regression coverage includes positive and negative fixtures for:

- dynamic collection sorting and multi-pass derivation
- memoized expensive collection work
- bounded and unbounded JSX list rendering
- trivial and identity-preserving `useMemo`
- repeated and single derived computations
- render-time and module-scope formatter construction
- dynamic and deferred `RegExp` construction
