## Implemented Rules

### `react.rsc.conflicting-boundary`

Detect modules that declare both `"use client"` and `"use server"` in the module directive prologue.

### `react.rsc.incompatible-boundary-import`

Detect `server-only` imports from an explicit client boundary and `client-only` imports from an explicit server boundary.

### `react.rsc.client-hook-in-server`

Detect React client-only hooks imported from `react` and invoked in an explicit server module.

### `react.rsc.browser-api-in-server`

Detect browser runtime globals such as `window`, `document`, storage APIs, and `navigator` in an explicit server module.

### `react.rsc.event-handler-in-server`

Detect executable DOM event handlers attached to intrinsic JSX elements in an explicit server module.

### `react.rsc.server-function-async`

Detect function-level `"use server"` directives on non-async functions.

### `react.rsc.server-function-in-client`

Detect inline Server Functions declared inside an explicit client module.

### `react.rsc.non-serializable-server-return`

Detect Server Function return values that are statically known to violate the serialization boundary, including executable closures, class values, `WeakMap`, `WeakSet`, and non-global `Symbol` values.

---

## Boundary Model

The RSC analyzer distinguishes four module states:

- `client` — explicit `"use client"` or `client-only` evidence
- `server` — explicit `"use server"` or `server-only` evidence
- `shared` — no explicit client/server evidence
- `conflict` — incompatible evidence from both boundaries

An unmarked file is deliberately treated as `shared`. The analyzer does not assume that absence of `"use client"` proves a Server Component because that would depend on framework configuration outside the current file.

---

## False-positive Protection

- React hook findings require the hook to be imported from `react` or called through a React namespace/default import.
- Local functions that merely use hook-like names are ignored.
- Browser-global findings are suppressed when the same identifier is locally bound.
- Event-handler findings are limited to lowercase intrinsic JSX elements; custom component props are not assumed to be client event handlers.
- Serialization findings only report values that are statically known to be unsupported.
- Function-level Server Function checks require an actual `"use server"` directive in the function body.
- No Next.js-specific path, API, or runtime assumptions are introduced into the core React plugin.
