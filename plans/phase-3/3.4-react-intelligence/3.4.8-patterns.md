## Implemented Rules

### React Query

React Query analysis is conditional. Rules activate only when APIs are statically imported from `@tanstack/react-query` or `react-query`.

#### `react.patterns.query-key-stability`

Detect query keys containing statically non-deterministic values such as:

- function expressions
- `new Date()`
- `Date.now()`
- `Math.random()`
- `crypto.randomUUID()`
- `performance.now()`

Local functions named `useQuery` do not activate this rule unless the React Query import can be resolved.

#### `react.patterns.query-effect-sync`

Detect effects whose only work is copying React Query data into local `useState` state.

The rule requires a statically resolved query binding, local state setter, and a single synchronization statement. Effects with additional side effects are not reported.

#### `react.patterns.query-cache-invalidation-render`

Detect `invalidateQueries`, `refetchQueries`, `resetQueries`, or `removeQueries` calls on a client returned by `useQueryClient()` when executed directly in the component render path.

Event handlers, effects, and other nested callbacks are excluded.

#### `react.patterns.mutation-in-render`

Detect `mutate()` / `mutateAsync()` calls from a statically resolved `useMutation()` binding when invoked directly during render.

Mutation calls deferred to event handlers or other nested callbacks are excluded.

---

### Suspense

#### `react.patterns.suspense-fallback`

Detect a `<Suspense>` fallback that statically contains a component created by React `lazy()`.

The rule only activates when `Suspense` and `lazy` are resolved from React imports. Synchronous fallbacks are accepted.

---

### Error Boundaries

#### `react.patterns.ineffective-error-boundary`

Detect React `Component` / `PureComponent` error boundaries that expose `componentDidCatch` or `getDerivedStateFromError` but have no statically visible recovery-state transition.

A non-null return from `getDerivedStateFromError` or a direct `this.setState()` in `componentDidCatch` is treated as recovery evidence.

The rule does not claim that every subtree requires an Error Boundary; it only evaluates boundaries that are already statically identifiable.

---

### Common React Anti-patterns

#### `react.patterns.nested-component-definition`

Detect a React component declaration inside another component boundary.

Nested component definitions create a new component type on parent renders and can remount the nested subtree. Module-scope component declarations are accepted.

---

## Conditional Activation

Framework/library-specific rules must activate only when the relevant dependency or API can be identified.

Phase 3.4.8 therefore does not add React Query as a runtime dependency. Static import analysis recognizes supported React Query packages only in source being reviewed.

---

## False-positive Protection

The implementation intentionally avoids lower-confidence assumptions:

- unrelated local APIs named like React Query hooks are ignored
- React Query render-side-effect rules require bindings resolved from recognized imports
- query-data synchronization requires an effect containing only the local state copy
- Suspense findings require a statically resolved `lazy()` component in the fallback
- Error Boundary findings require an actual React component subclass and visible error-boundary lifecycle API
- nested components are resolved through existing React component semantic metadata

---

## Validation Coverage

Regression coverage includes positive and negative fixtures for:

- deterministic and non-deterministic React Query keys
- React Query import activation guards
- query data mirrored into local state
- effects containing additional side effects
- cache invalidation during render versus event handlers
- mutations during render versus event handlers
- lazy versus synchronous Suspense fallbacks
- ineffective versus state-recovering Error Boundaries
- nested versus module-scope component declarations
- built-in React plugin registration and execution
