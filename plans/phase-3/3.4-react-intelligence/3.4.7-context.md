# Phase 3.4.7 — React Context Intelligence

> Engineering contract: [`../../../AGENTS.md`](../../../AGENTS.md)

Status: ✅ Complete

---

## Objective

Analyze React Context usage for architectural and rendering performance issues.

---

## Implemented Semantic Analysis

Context analysis now identifies:

- `createContext(...)` and `React.createContext(...)` definitions
- matching `<Context.Provider>` JSX boundaries
- provider `value` expressions
- the enclosing React component
- render-scope variable/function bindings referenced by provider values
- stable `useMemo` / `useCallback` values
- component props, state, `useContext` values, and one-level derived dynamic bindings
- nested provider ancestry and statically equivalent provider value expressions

Analysis is cached per AST so all Context rules share the same provider model.

---

## Implemented Rules

### `react.context.unstable-value`

Detect provider values whose identity is recreated during provider render:

- inline object values
- inline array values
- inline function values
- render-scope object/array/function bindings passed by identifier

False-positive protection:

- module-scope values are treated as stable
- `useMemo` object values are accepted
- `useCallback` function values are accepted
- unknown function-call results are not assumed to be unstable

---

### `react.context.consumer-invalidation`

Detect broad memoized provider objects that combine at least three independently changing render inputs.

The rule only reports when static evidence proves that one Context value couples several dynamic inputs. Findings describe Context invalidation semantics rather than claiming measured runtime regressions.

Suggested remediation is to split Context by responsibility or update cadence when consumers do not need the complete value.

---

### `react.context.provider-nesting`

Detect statically identifiable provider composition issues:

- the same Context nested with the same visible value expression
- provider composition reaching five nested Context providers

Intentional same-Context overrides with different values are not reported.

---

## Requirements

Use semantic provider/value analysis.

Do not report performance issues without sufficient static evidence.

---

## Validation Coverage

Regression coverage includes positive and negative fixtures for:

- inline and render-scope unstable provider values
- memoized provider objects
- module-scope stable values
- React namespace `createContext`
- broad memoized Context values with props/state/derived inputs
- focused Context values below the invalidation threshold
- duplicated nested providers
- intentional Context overrides
- five-provider deep composition
- provider nesting below the threshold
- built-in React plugin registration and execution
