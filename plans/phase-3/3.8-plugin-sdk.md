# Phase 3.8 — Plugin SDK

> Engineering contract: [`../../AGENTS.md`](../../AGENTS.md)

Status: ✅ Complete

---

## Objective

Make the reviewer extensible through a typed plugin system without weakening the deterministic-first architecture or introducing framework dependencies.

---

## Architecture

```text
Core Engine
│
├── Rule Plugins
├── React Plugins
├── Custom Deterministic Analyzers
├── AI Providers
└── Output Adapters
        │
        ▼
   Plugin Registry
        │
        ▼
 Typed Plugin Runtime
```

The SDK is implemented under `src/plugins/` and reuses existing domain contracts rather than duplicating rule, React, AI, or review types.

---

## Public SDK

### `ReviewerPlugin`

A plugin has immutable metadata and may contribute:

- AST rules
- React plugins
- deterministic analyzers
- AI providers
- output adapters

### `PluginRegistry`

The registry:

- registers plugins explicitly
- rejects duplicate plugin IDs
- rejects duplicate contribution IDs/names
- exposes immutable snapshots
- resolves AI providers by name
- resolves output adapters by ID

No global mutable singleton is used. Callers own registry lifecycle.

### `analyzeWithPlugins`

The plugin runtime composes:

1. built-in deterministic analyzers
2. contributed AST rules
3. contributed deterministic analyzers
4. contributed React plugins for JSX/TSX files

Built-in behavior is unchanged when no plugin contributions are provided.

---

## Engineering Constraints

- Strict TypeScript
- No `any`
- No unsafe casts
- No runtime dependency added
- Existing rule/domain contracts are reused
- Plugin registration is deterministic
- Duplicate contribution identity fails fast
- AI providers remain injected dependencies
- Output adapters do not mutate review-domain results
- Plugin runtime does not call GitHub APIs
