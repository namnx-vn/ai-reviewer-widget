# Phase 3.6.18 — React / Browser Banking Security

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Add React-specific/browser banking security checks while preserving the React architectural boundary.

## Dependencies
- 3.6.0
- Existing React semantic/component/JSX/scope/declaration analyzers
- Shared security source/sink/taint primitives

## Rules
```text
security.react.dangerously-set-inner-html
security.react.untrusted-href
security.react.untrusted-src
security.react.external-form-action
security.react.sensitive-local-storage
security.react.sensitive-session-storage
security.react.sensitive-query-param
security.react.third-party-script
security.react.unsafe-iframe
security.react.unsafe-post-message
security.react.missing-opener-protection
security.react.sensitive-autocomplete
```

## Detection Contract
Reuse existing component detection, JSX analysis, scope/declaration resolution, and prop resolution. Do not build a separate JSX traversal per rule. High-value contexts include payment forms, account identifiers, authentication, OTP, transaction confirmation, external redirects, scripts, iframes, and postMessage.

Implementation registers the banking rules in the existing React plugin and relies on the React engine's single AST traversal plus shared JSX utilities. Local declaration resolution handles simple aliases, while generic sensitive-data classification and stable security finding IDs are consumed from the security boundary; generic security code never imports React-specific modules.

## Tests
JSX attributes, props/aliases, tainted URLs/HTML, safe URLs, sensitive form fields, storage, external scripts/forms, iframe/postMessage, opener protection, autocomplete behavior, and existing React semantic edge cases.

## Exit Criteria
React rules remain under the React boundary while consuming shared generic security primitives.
