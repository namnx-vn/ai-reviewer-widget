# Phase 3.6.7 — Authorization Intelligence

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Detect authorization anti-patterns and high-confidence access-control risks using explicit security semantics.

## Dependencies
- 3.6.0
- 3.6.19
- 3.6.20 for cross-function resource/identity flows

## Rules
```text
security.authz.client-side-only
security.authz.role-from-untrusted-input
security.authz.permission-from-untrusted-input
security.authz.mass-assignment
security.authz.missing-resource-ownership
security.authz.idor-candidate
security.authz.privilege-escalation
```

## Detection Contract
Model authenticated principal, resource identifier, ownership, role, permission, and privileged operation as reusable semantics. IDOR/ownership findings must not claim certainty when the analyzer cannot prove missing ownership enforcement; emit candidate findings with reduced confidence when context is incomplete.

Implementation uses the shared 3.6.19/3.6.20 taint API for untrusted role/permission propagation and explicit structural authorization semantics for client-side enforcement, persistence mutation boundaries, ownership checks, and IDOR candidates. Ownership/IDOR findings remain medium-confidence when enforcement may exist outside the analyzed unit.

## Tests
Trusted/untrusted role sources, ownership checks, resource lookups, mass assignment, middleware/wrapper paths where supported, false positives, and incomplete-context confidence behavior.

## Exit Criteria
Authorization findings clearly distinguish proven violation from candidate risk and never rely on identifier names alone.
