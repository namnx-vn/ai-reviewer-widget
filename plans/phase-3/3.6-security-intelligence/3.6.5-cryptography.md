# Phase 3.6.5 — Cryptography Intelligence

> Parent: [Security Intelligence](./README.md)

Status: ⏳ Planned

## Objective
Identify deterministic misuse of cryptographic and randomness primitives.

## Dependencies
- 3.6.0

## Rules
```text
security.crypto.weak-hash
security.crypto.weak-cipher
security.crypto.ecb-mode
security.crypto.static-iv
security.crypto.hardcoded-key
security.crypto.insecure-random
security.crypto.predictable-token
security.crypto.password-without-kdf
security.crypto.weak-kdf
security.crypto.custom-crypto
```

## Detection Contract
Separate API detection, algorithm/parameter extraction, and policy evaluation. Acceptable algorithms/key sizes must be policy-driven rather than duplicated across rules.

Differentiate security-sensitive hashing/password/token contexts from non-security fingerprints where evidence permits. Unknown/dynamic algorithms must carry appropriate confidence instead of invented certainty.

## Tests
Node crypto, Web Crypto, weak/strong algorithms, ECB/static IV/hardcoded key, `Math.random`, secure random APIs, password hashing, dynamic algorithms, aliases, and safe cases.

## Exit Criteria
Crypto policy can evolve independently of AST/API detection; all findings are context-aware and deterministic.
