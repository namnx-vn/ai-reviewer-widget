## Detection Contract
API detection, algorithm/parameter extraction, and policy evaluation are separated. The shared `CryptoPolicy` owns weak hash/cipher families, ECB patterns, PBKDF2 thresholds, and security-context naming patterns rather than duplicating them across rules.

Node `crypto` and Web Crypto are modeled independently from policy decisions. Supported Node patterns include namespace/default/named/aliased imports and CommonJS bindings. Supported Web Crypto patterns include global `crypto.subtle`, `window.crypto.subtle`, `globalThis.crypto.subtle`, imported `webcrypto`, and namespace `webcrypto.subtle` access.

Weak-hash confidence is context-aware: password/token/key material contexts are high-confidence while generic checksum/fingerprint-like use remains medium-confidence. Dynamic algorithms and dynamic KDF parameters are not classified as weak without deterministic evidence.

`Math.random()` is only considered insecure when its surrounding binding/function context indicates cryptographic material or a security token; unrelated UI/random-layout usage is suppressed. Password use of a general-purpose hash is separately reported from weak-hash policy.

## Implementation
- `src/analyzer/security/policies/crypto-policy.ts`
  - configurable weak hashes/ciphers/ECB modes
  - PBKDF2 minimum iteration policy
  - password/token/key-material/custom-crypto context patterns
- `src/analyzer/security/rules/crypto/crypto-model.ts`
  - deterministic Node/Web Crypto API identity resolution
  - algorithm, key, IV/nonce, KDF parameter extraction
  - hardcoded key-material recognition
  - security-sensitive random context extraction
  - custom crypto-like implementation observation
- `src/analyzer/security/rules/crypto/crypto-rules.ts`
  - policy evaluation and deterministic findings
  - CWE mappings, severity/confidence, exact evidence locations
- public exports through `src/analyzer/security/index.ts`

## Exit Criteria
✅ Crypto policy evolves independently of AST/API detection.

✅ Findings are context-aware and deterministic.

✅ Dynamic algorithms/parameters are not assigned unsupported certainty.

✅ Node crypto and Web Crypto safe/unsafe cases have regression coverage.

## Out of Scope
- Runtime cryptanalysis or proving cryptographic strength of unknown third-party implementations.
- Cross-file value resolution for dynamic algorithm names or KDF parameters; that belongs to later interprocedural analysis.
- Organization-specific approved algorithm catalogs beyond the configurable default policy.
