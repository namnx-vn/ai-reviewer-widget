# Phase 3.6.22 — Banking Security Profile

> Parent: [Security Intelligence](./README.md)

Status: 🚧 Implemented — validation pending

## Objective
Provide explicit policy profiles culminating in a strict banking configuration without changing underlying detection semantics.

## Dependencies
- 3.6.0 policy metadata
- Core rule families available
- 3.6.21 for optional compliance labels

## Profiles
```text
security/default
security/strict
security/financial
security/banking
```

Inheritance:
```text
default → strict → financial → banking
```

## Policy Controls
Profiles may change enabled state, severity override, minimum confidence, allowed crypto algorithms/parameters, allowed storage mechanisms, allowed transport, and quality-gate behavior.

Typical banking mandatory findings include secret/payment-data/credential exposure, TLS verification disabled, command/SQL injection, SSRF, unverified JWT, client-side-only authorization, insecure randomness, and unsafe dynamic execution.

## Critical Contract
Profiles interpret the same underlying finding/evidence. They MUST NOT redefine AST/data-flow detection or create duplicated banking-specific copies of generic rules.

## Implementation
- Added deterministic profile definitions under `src/analyzer/security/policies/security-profiles.ts`.
- Implemented inheritance resolution with duplicate-profile, unknown-parent, and circular-inheritance protection.
- Implemented per-rule enable/disable, severity override, and minimum-confidence policy controls.
- Added explicit crypto policy metadata for algorithm allowlists, PBKDF2 minimum iterations, and RSA minimum key size.
- Added browser/server storage allowlists and transport policy for TLS, certificate verification, and minimum TLS version.
- Added quality-gate policy metadata with blocking severities, confidence threshold, and mandatory rule IDs; Phase 3.6.23 remains responsible for executing quality gates.
- `applySecurityProfile()` runs after detection and preserves finding ID, evidence, flow, standards, and sink evidence; only filtering/policy severity interpretation can change.
- Added raw security-evidence and compliance-report APIs with `security/default` as the backward-compatible default profile.

## Tests
Inheritance, overrides, rule enable/disable, confidence thresholds, crypto/storage/network policy, stable evidence across profiles, and deterministic merged configuration.

Implemented coverage includes standard inheritance lineage, custom enable/disable and severity/confidence overrides, banking transport/storage/mandatory-rule inheritance, evidence/flow/ID preservation, confidence filtering, and invalid/circular profile rejection.
