# Phase 3.6.9 — Sensitive Data Protection

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Classify and track sensitive banking/payment/authentication data into exposure sinks.

## Dependencies
- 3.6.0
- 3.6.19

## Initial Data Classes
```text
password
PIN
OTP
PAN
CVV/CVC
bank account identifier
access token
refresh token
private key
national identifier
personal identifier
transaction detail
balance
```

## Rules
```text
security.data.log-sensitive
security.data.url-sensitive
security.data.client-storage-sensitive
security.data.telemetry-sensitive
security.data.analytics-sensitive
security.data.error-sensitive
security.data.unencrypted-persistence
security.data.clipboard-sensitive
```

## Detection Contract
Classification may use identifier/property semantics, explicit source type, schema-like context, and future annotations, but it must remain deterministic. Values may carry multiple data classifications. Analyzer output must never reveal full sensitive values.

## Tests
Classification, propagation, logging, URL/query, storage, telemetry/analytics, error objects, safe redaction, false-positive identifiers, and mixed sensitive/non-sensitive flows.

## Exit Criteria
Sensitive data classes integrate with the shared taint model and all outputs redact value material.
