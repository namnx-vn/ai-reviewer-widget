# Phase 3.6.0 — Security Architecture Foundation

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Create stable domain contracts and registries used by every later security phase.

## Dependencies
- `AGENTS.md`
- Existing analyzer/parser/review-domain abstractions
- No dependency on later 3.6 phases

## Deliverables
Define typed contracts for `SecurityRule`, `SecurityRuleMeta`, `SecurityRuleContext`, `SecurityFinding`, `SecuritySeverity`, `SecurityConfidence`, `SecurityCategory`, `SecurityEvidence`, `SecurityLocation`, `SecurityStandardMapping`, `SecuritySourceKind`, `SecuritySinkKind`, `SecuritySanitizerKind`, and `SecurityFlowStep`.

Create a centralized security rule registry with duplicate-ID rejection, stable iteration order, category lookup, policy lookup, and enable/disable support.

Finding IDs must be deterministic from stable inputs such as rule ID, path, node range, and sink kind. Never use random UUIDs, timestamps, or mutable counters.

## Detection Contract
This phase introduces no production vulnerability rules. It establishes immutable/shared context and deterministic result contracts only.

## Tests
Cover rule registration, duplicate IDs, stable IDs, stable ordering, metadata validation, severity/confidence validation, empty output, multiple findings, and rule failure isolation semantics.

## Exit Criteria
- Contracts compile under strict TypeScript.
- Registry ordering/fingerprints are deterministic.
- No LLM/GitHub/UI coupling exists.
- `typecheck`, `lint`, `test`, and `build` pass.

## Out of Scope
Taint propagation, call graph, framework source models, compliance reporting, policy profiles, and quality gates.
