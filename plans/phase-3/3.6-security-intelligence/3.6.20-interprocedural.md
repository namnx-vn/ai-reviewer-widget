# Phase 3.6.20 — Interprocedural Security Analysis

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Extend shared security flow across function boundaries and, incrementally, file/module boundaries.

## Dependencies
- 3.6.0
- 3.6.19 stable
- Existing declaration/import/export resolution should be reused

## Rollout
### 3.6.20-A — Local Call Graph
Function declarations, function expressions, arrow functions, identifier references, and direct calls.

### 3.6.20-B — Parameter Propagation
Track argument taint into resolved parameters and sinks.

### 3.6.20-C — Return Propagation
Track tainted return values back to callers.

### 3.6.20-D — Same-file Function Summaries
Create deterministic summaries such as parameter-to-return and parameter-to-sink flows.

### 3.6.20-E — Cross-file Summaries
Resolve supported imports/exports and consume stable summaries without reanalyzing arbitrary modules repeatedly.

## Safety Controls
Prevent infinite recursion, cyclic traversal, exponential path explosion, and unbounded call depth. Limits must be deterministic/configurable. Unknown calls must not automatically sanitize attacker-controlled data.

## Tests
Nested calls, wrappers, returns, recursion, cycles, callbacks where supported, aliases, same-file summaries, imports/exports, unresolved calls, deterministic depth limits, and stable evidence paths.

## Exit Criteria
Cross-function flow uses one shared call-graph/summary system and remains bounded/deterministic.
