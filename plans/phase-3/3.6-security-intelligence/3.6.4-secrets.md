# Phase 3.6.4 — Secrets & Credential Exposure

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Detect embedded or exposed credentials while controlling false positives and never leaking the secret in analyzer output.

## Dependencies
- 3.6.0

## Rules
```text
security.secrets.hardcoded-password
security.secrets.api-key
security.secrets.access-token
security.secrets.refresh-token
security.secrets.private-key
security.secrets.jwt
security.secrets.database-url
security.secrets.secret-in-url
security.secrets.secret-in-log
security.secrets.client-exposure
```

## Detection Contract
Use combined deterministic evidence: known prefixes, identifier/property semantics, string structure, entropy signal, and surrounding context. Regex alone must not decide every finding.

Support explicit handling for placeholders, masked values, documentation examples, configured test fixtures, and environment-variable references. Findings, snapshots, logs, and evidence MUST redact actual secret material.

## Tests
Realistic token/key shapes, placeholders, masked values, env lookups, private key blocks, JWT-like strings, URL/log exposure, client bundling context, test fixture behavior, and redaction.

## Exit Criteria
Secret material never appears unredacted in generated findings; false-positive controls are covered by regression tests.
