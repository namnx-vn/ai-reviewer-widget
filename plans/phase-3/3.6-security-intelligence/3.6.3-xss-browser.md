## Detection Contract
Model browser sources such as location/search/hash/document URL, message event data, storage values, and untrusted arguments. Model sinks such as `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, location/navigation, redirect, and `window.open`.

HTML sanitizers and URL validators are separate. URL encoding never counts as generic HTML sanitization and HTML sanitization never clears URL/navigation risk.

## Implemented Architecture

Phase 3.6.3 extends the shared security flow primitives instead of creating a browser-specific taint engine. Shared sink modeling now supports both call-expression and assignment sinks, which allows DOM property and browser navigation assignments to consume the same deterministic intraprocedural flow machinery used by injection intelligence.

Browser modeling is centralized under `src/analyzer/security/rules/browser/` and separates HTML, URL, navigation, window-open, and postMessage-origin taint kinds. Modeled browser sources include location URL components, document URL/referrer values, message-event data, browser storage reads, cookies, and `window.name`.

Modeled sanitization is sink-aware:

- HTML sanitizers clear only HTML taint.
- Modeled URL sanitizers clear URL-property taint only.
- HTML sanitization does not validate redirect destinations.
- URL sanitization does not establish trusted redirect, window-open, or postMessage origins.
- URL encoding is not treated as HTML sanitization.

The implementation also detects statically provable `javascript:` URLs and wildcard `postMessage` target origins without requiring taint, because those patterns are intrinsically unsafe at the modeled sink.

## 3.6.19 / 3.6.20 Boundary

The shared intraprocedural flow slice used here is intentionally reusable infrastructure, not a declaration that Phase 3.6.19 is complete. Phase 3.6.19 remains responsible for the mature shared taint engine and broader propagation semantics. Phase 3.6.20 remains responsible for cross-function and cross-file analysis.

No browser rule owns a private taint engine.

## Exit Criteria
Browser/XSS findings provide exact sink evidence, sanitizer classes are not conflated, false-positive regressions are covered, deterministic behavior is preserved, and repository validation passes.
