# Phase 3.6.21 — Compliance Mapping

> Parent: [Security Intelligence](./README.md)

Status: 🚧 Implemented — validation pending

## Objective
Attach validated standards traceability to security rules/findings without claiming certification or compliance.

## Dependencies
- 3.6.0 metadata contracts
- Core rule families sufficiently stable for mapping

## Deliverables
Support mappings for CWE, OWASP Top 10, OWASP ASVS, PCI DSS, NIST SSDF, and internal policy identifiers through centralized/validated metadata.

Coverage states:
```text
covered
partially-covered
manual-verification-required
not-applicable
not-implemented
```

## Contract
Avoid arbitrary repeated free-form standard IDs when a registry can validate them. Reports may say `mapped controls`, `automated coverage`, or `manual verification required`; they MUST NOT say `PCI compliant`, `ASVS compliant`, or `bank compliant` from static results alone.

## Implementation
- Added `src/analyzer/security/compliance/` as the centralized compliance boundary.
- Added standard-ID validation for CWE, OWASP Top 10, versioned OWASP ASVS, PCI DSS, NIST SSDF, and internal banking-policy identifiers.
- Added `ComplianceRegistry` with deterministic lookup, invalid-ID rejection, duplicate-mapping rejection, and rationale requirements.
- Added mapping enrichment that merges centralized mappings with rule-provided standards without changing finding IDs, evidence, or flow.
- Added deterministic compliance reports with per-control coverage aggregation and an explicit non-certifying disclaimer.
- Default mappings use current OWASP Top 10:2025 categories and versioned OWASP ASVS 5.0.0 identifiers for mapped controls.
- PCI DSS mappings are deliberately marked partial where static analysis cannot establish operational scope, script authorization/integrity/inventory, or deployment controls.

## Tests
Known mappings, invalid IDs, duplicate mappings, coverage aggregation, partial/manual coverage, deterministic reporting, and wording safeguards.

Implemented coverage includes supported ID validation, invalid/duplicate rejection, mapping deduplication, conservative multi-rule coverage aggregation, evidence preservation, deterministic ordering, and non-certifying wording.
