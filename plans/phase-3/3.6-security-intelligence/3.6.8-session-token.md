# Phase 3.6.8 — Session & Token Security

> Parent: [Security Intelligence](./README.md)

Status: ✅ Complete

## Objective
Detect insecure session, cookie, bearer-token, and JWT handling patterns.

## Dependencies
- 3.6.0
- 3.6.22 later supplies stricter banking policy overrides

## Rules
```text
security.session.local-storage-token
security.session.session-storage-token
security.session.cookie-http-only
security.session.cookie-secure
security.session.cookie-same-site
security.session.token-in-url
security.session.predictable-session-id
security.jwt.none-algorithm
security.jwt.unverified
security.jwt.exp-validation
security.jwt.issuer-validation
security.jwt.audience-validation
security.jwt.weak-secret
```

## Detection Contract
Storage findings are policy-sensitive: generic detection evidence remains stable while severity may differ between default/strict/banking profiles. Cookie analysis only applies to cookie creation/configuration, not reads. JWT rules must use known verification/signing semantics rather than string matching.

## Tests
Cookie option objects, token persistence, URLs/query strings, secure/unsafe JWT configuration, verification checks, dynamic options, aliases, and profile severity behavior.

## Exit Criteria
Underlying evidence is profile-independent and deterministic; policy changes do not alter detection semantics.
