# Phase 3.6.1 — Dangerous Execution

> Parent: [Security Intelligence](./README.md)

Status: ⏳ Planned

## Objective
Detect direct dangerous dynamic code execution with low-noise semantic matching.

## Dependencies
- 3.6.0 complete
- Existing scope/declaration resolution should be reused when available

## Rules
```text
security.execution.no-eval
security.execution.no-indirect-eval
security.execution.no-new-function
security.execution.no-dynamic-code
security.execution.no-vm-execution
```

## Detection Contract
Detect direct/member/obvious alias forms such as `eval(input)`, `globalThis.eval(input)`, `window.eval(input)`, `new Function(input)`, and explicitly modeled Node VM execution APIs. Do not flag unrelated user-defined identifiers merely named like dangerous APIs.

Direct dangerous API use can be reported without taint analysis; attacker-controlled execution is upgraded later through 3.6.19.

## Tests
Positive: direct call, member call, alias, constructor, multiline, TypeScript, JSX module. Negative: unrelated `evaluate`, strings containing `eval`, unrelated object methods, shadowed identifiers when semantic identity proves shadowing.

## Exit Criteria
Direct dynamic execution detection is deterministic, stable, and low-noise; all validation passes.

## Out of Scope
Source-to-execution taint flow, cross-function propagation, and framework request-source modeling.
