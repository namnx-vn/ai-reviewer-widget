# Phase 3.6.6 — Authentication Intelligence

> Parent: [Security Intelligence](./README.md)

Status: ⏳ Planned

## Objective
Detect deterministic authentication anti-patterns without trying to prove that arbitrary applications have complete authentication.

## Dependencies
- 3.6.0
- Prefer 3.6.19 and 3.6.20 for flow-aware rules

## Rules
```text
security.auth.hardcoded-credential
security.auth.plaintext-password
security.auth.weak-password-storage
security.auth.authentication-bypass
security.auth.client-side-auth
security.auth.user-enumeration
security.auth.password-reset-token
security.auth.oauth-state-missing
security.auth.oauth-pkce-missing
security.auth.jwt-decode-without-verify
```

## Detection Contract
Only report patterns backed by deterministic evidence. JWT analysis must distinguish decode, verify, and sign. Decoding a token never counts as verification. Authentication presence/absence across an unknown application is not inferred globally.

## Tests
Direct patterns, wrappers, aliases, known-safe verify paths, password storage/hashing, reset-token generation, OAuth state/PKCE configurations, false-positive regressions, and incomplete-context confidence.

## Exit Criteria
Authentication findings do not overclaim global application security and use flow evidence where required.
