# Phase 3.6.23 — Security Quality Gates

> Parent: [Security Intelligence](./README.md)

Status: 🚧 Implemented — validation pending

## Objective
Convert deterministic security findings and policy into CI/PR pass/warn/fail decisions without coupling the domain layer to GitHub presentation.

## Dependencies
- 3.6.0
- 3.6.22 policy profiles
- Stable finding fingerprints

## Gate Inputs
Severity, confidence, active profile, baseline/new status, category/rule, and explicit audited suppressions.

Recommended banking defaults:
```text
new critical → fail
new high → fail
new secret exposure → fail
new medium → configurable
new low → report
existing debt → baseline
```

## Baseline Contract
Adoption should support blocking newly introduced vulnerabilities without requiring all historical debt to be fixed immediately. Baseline matching uses stable fingerprints.

## Suppression Contract
Suppression is applied after detection and must be explicit/auditable. Target model includes rule ID/fingerprint, reason, optional owner, and optional expiry. Anonymous permanent `security-ignore` comments are not the desired contract.

## Output
Return structured `pass`, `warn`, or `fail` plus deterministic reasons. GitHub integration decides how to render/publish that result.

## Implementation
- Added `src/analyzer/security/quality-gate/` as a presentation-independent quality-gate boundary.
- Added deterministic `pass` / `warn` / `fail` decisions with stable finding/reason ordering and structured per-finding actions.
- Baseline matching uses the existing deterministic finding ID as the stable fingerprint; matching debt remains visible but does not block adoption.
- Added explicit suppressions by finding fingerprint and/or rule ID with mandatory reason, optional owner, optional expiry, and structured suppression audit output.
- Suppression expiry requires an explicit ISO `evaluatedAt` input. The gate never reads the system clock, so expiry evaluation is reproducible.
- Added profile-aware enable/disable, effective severity, rule confidence, gate confidence, mandatory-rule, severity, and category policy handling.
- Active profile blockers and mandatory rule IDs take precedence over configurable category/severity advisory actions, so callers cannot silently weaken a banking blocker through an ad-hoc medium/low action override.
- Banking mandatory policy now covers the full secret-exposure rule family in addition to injection, TLS verification, JWT verification, authorization, SSRF, insecure randomness, dynamic execution, sensitive browser storage, idempotency, and replay findings.
- Added a review-domain adapter that consumes only `ReviewFinding` objects with `source: "security"`, allowing React/browser and supply-chain security findings to use the same gate without coupling the core gate to React or GitHub.
- Centralized rule-profile interpretation in `resolveSecurityRulePolicy()` so profile application and quality-gate evaluation share the same enable/severity/confidence semantics.
- Closed a production-registry integration gap by registering dangerous-execution, injection, browser/XSS, and crypto rule families in the source security registry before gate evaluation.

## Tests
New vs baseline findings, severity/confidence thresholds, profile overrides, suppressions/expiry semantics where implemented, stable fingerprints, deterministic reason ordering, and no GitHub coupling.

Implemented coverage includes banking high-severity blocking, mandatory secret findings, baseline debt, configurable medium action, report-only low findings, category policy, active/expired and rule-level suppressions, profile disablement/confidence thresholds, deterministic input-order independence, invalid timestamps/suppressions/duplicate policy rejection, review-domain filtering/confidence normalization, and production-registry coverage for gate-critical security families.
