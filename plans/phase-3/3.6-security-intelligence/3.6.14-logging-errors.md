# Phase 3.6.14 — Logging & Error Security

> Parent: [Security Intelligence](./README.md)

Status: 🚧 Implemented — validation pending

## Objective
Detect security-sensitive data leakage through logs/errors and unsafe internal-detail exposure.

## Dependencies
- 3.6.0
- 3.6.9 data classification for mature sensitive-data logging rules
- 3.6.19 for flow-aware exposure

## Rules
```text
security.logging.secret
security.logging.credential
security.logging.payment-data
security.logging.pii
security.error.stacktrace-exposure
security.error.internal-detail
security.error.database-detail
```

## Detection Contract
Security-sensitive logging remains distinct from generic `no-console` style rules. Report based on data classification and explicit error-response sinks. Do not implement `missing-audit-event` until application/event semantics are reliable enough to avoid speculative findings.

Implementation extracts the 3.6.9 sensitive-data classifier into a shared deterministic primitive consumed by both sensitive-data and logging rules. Logging uses interprocedural taint plus explicit redaction semantics; error rules only inspect explicit client-response sinks and never copy captured sensitive/error values into findings.

## Tests
Secrets/payment/PII in logs, errors returned to clients, database/internal errors, structured logging, redaction, safe generic messages, and false-positive regressions.

## Exit Criteria
Leakage findings reuse shared data classifications and never reveal captured sensitive values.
