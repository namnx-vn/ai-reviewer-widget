# Phase 3.7.10 — Cache Intelligence

> Parent: [Phase 3.7](./README.md)

Status: ✅ Complete

## Objective

Detect cache designs that create memory growth, stampedes, stale financial data risk, or redundant recomputation.

## Rules

```text
performance.cache.unbounded
performance.cache.missing-ttl
performance.cache.stampede-risk
performance.cache.recompute-on-miss
performance.cache.critical-data-without-freshness-policy
```

## Banking Constraint

Sensitive-data confidentiality remains Phase 3.6 responsibility. Phase 3.7 focuses on performance/freshness behavior and may reference security metadata without duplicating security rules.

## Implementation

Implemented in `src/analyzer/performance/rules/cache-rules.ts` and exported through the shared performance rule registry surface.

Detection is intentionally evidence-based and deterministic:

- mutable in-memory cache growth requires cache mutation plus absence of visible eviction/capacity evidence;
- TTL/freshness findings require a cache write without visible expiration/freshness configuration;
- stampede/recompute findings require both cache-read evidence and modeled expensive downstream work;
- critical-data freshness uses deterministic financial-domain identifiers and does not duplicate Phase 3.6 confidentiality findings.

## Tests
