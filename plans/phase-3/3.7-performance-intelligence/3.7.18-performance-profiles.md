# Phase 3.7.18 — Performance Profiles

> Parent: [Phase 3.7](./README.md)

Status: ✅ Complete

## Objective

Separate deterministic detection from organization-specific performance policy.

## Profiles

```text
performance/default
performance/strict
performance/financial
performance/banking
```

Inheritance:

```text
default → strict → financial → banking
```

## Policy Controls

Profiles may define:

- enabled rules;
- severity overrides;
- minimum confidence;
- thresholds;
- critical route/entrypoint configuration;
- approved concurrency bounds;
- timeout expectations;
- retry limits;
- cache constraints;
- quality-gate behavior.

## Invariant

Profiles MUST NOT change underlying detection evidence. The same source analyzed under two profiles should preserve findings/evidence, with policy interpretation changing where applicable.

## Tests

Cover inheritance, overrides, invalid configuration, deterministic resolution, and banking severity escalation.
