# Phase 3.7.12 — Resilience, Timeout & Retry

> Parent: [Phase 3.7](./README.md)

Status: ⏳ Planned

## Objective

Detect call patterns that can hang, amplify incidents, or exceed latency budgets under partial failure.

## Rules

```text
performance.resilience.missing-timeout
performance.resilience.unbounded-retry
performance.resilience.retry-without-backoff
performance.resilience.retry-without-jitter
performance.resilience.retry-non-idempotent
performance.resilience.retry-amplification
```

## Detection Contract

Timeout detection requires modeled client/config semantics. Unknown libraries MUST NOT be treated as definitely missing timeouts.

Retry semantics MUST distinguish bounded retries, exponential/backoff helpers, idempotent operations, and transaction-sensitive operations.

## Tests

Cover fetch/client wrappers, explicit timeout/abort, retry loops, bounded retry counts, backoff, jitter, idempotency evidence, and safe cases.
