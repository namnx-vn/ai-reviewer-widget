# Phase 3.7.16 — Performance Cost Propagation

> Parent: [Phase 3.7](./README.md)

Status: ✅ Complete

## Objective

Create a reusable deterministic model for propagating performance-relevant operation costs through expressions and local control flow.

## Cost Kinds

Initial categories include:

```text
network
filesystem
database
serialization
cpu-heavy
allocation
render
external-service
```

Costs are symbolic categories, not fabricated milliseconds.

## Propagation

The shared analyzer identifies modeled operations and records deterministic local-path evidence including assignment, return, conditional, and repeated-loop context where visible.

`PerformanceOperation` supports a primary cost kind plus multiple symbolic cost kinds so one operation can represent combined semantics such as `network + external-service` without reducing cost to a boolean.

## Critical Invariant

Do NOT reduce the model to `expensive: true`. One operation can carry multiple cost kinds and contextual properties such as blocking, repeated, bounded, or external.

## Implementation

Implemented in `src/analyzer/performance/cost/cost-propagation.ts` and exported as `analyzePerformanceCosts` from the performance package boundary.

The analyzer currently models:

- `fetch`, axios, and Node HTTP request operations;
- configured database adapters;
- filesystem operations;
- JSON serialization/deserialization;
- sort CPU work;
- repeated loop context;
- blocking `*Sync` semantics;
- assignment/return/conditional path evidence;
- stable operation/path ordering and deterministic de-duplication.

Phase 3.7.17 MUST consume this public cost-summary contract rather than creating a competing cost engine.

## Tests

Covered by `src/analyzer/performance/__tests__/wave-5-rules.test.ts`:

- deterministic repeated analysis;
- multiple cost kinds on one operation;
- loop/repeated context;
- stable path evidence ordering.

## Exit Criteria

Rules can consume one shared cost model rather than implementing private structural analysis.
