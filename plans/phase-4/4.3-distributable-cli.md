# Phase 4.3 — Distributable CLI

> Engineering contract: [`../../AGENTS.md`](../../AGENTS.md)

Status: ⏳ Planned

Depends on: Phase 4.2

---

## Objective

Evolve the repository-local `review:local` script into a stable distributable CLI surface without duplicating review logic or coupling the application layer to Node process APIs.

---

## Scope

### 1. Public CLI Contract

Define a stable executable contract for commands already proven by Phase 4.1:

```text
ai-reviewer review
ai-reviewer review --diff
ai-reviewer review --file <path>
ai-reviewer rules
ai-reviewer init
```

Preserve stable exit semantics:

- `0` — successful review / passing decision
- `1` — completed review with failing decision
- `2` — invalid usage, configuration, or operational failure

### 2. Package Surface

Prepare package metadata and exports required for distribution.

Requirements:

- one supported CLI entry point
- explicit package/bin exports
- no dependence on Vite/browser entry points
- no accidental publication of internal-only modules
- version output and help output are deterministic
- package build remains compatible with the repository's TypeScript/ESM stack

Any packaging dependency or build change requires explicit justification before implementation.

### 3. Process Adapter

Keep `process.argv`, stdout/stderr, exit-code assignment, and filesystem concerns in the CLI adapter.

The CLI must continue to delegate review execution to the shared application review use cases.

### 4. Machine-Readable Output

Add an explicit output-mode contract suitable for automation, initially:

```text
--format text
--format json
```

JSON output must use a versioned/stable schema derived from review-domain contracts rather than terminal strings.

### 5. Distribution Validation

Validate the packed artifact rather than only source execution.

Tests should cover:

- packaged executable invocation
- help/version
- config discovery
- file/diff review
- JSON output
- exit codes

---

## Non-Goals

- CI-provider-specific orchestration
- hosted API client
- automatic global install flows
- plugin marketplace
- self-update mechanism

---

## Acceptance Criteria

- [ ] A documented executable entry point exists.
- [ ] The packaged CLI invokes the same application review pipeline as local/GitHub paths.
- [ ] Existing Phase 4.1 command semantics are preserved.
- [ ] Text and JSON output modes are deterministic and tested.
- [ ] Package exports do not expose accidental internal implementation surfaces.
- [ ] Packed-artifact smoke tests execute successfully.
- [ ] No browser/UI dependency is required to execute the CLI.
- [ ] `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` pass.
