# Phase 4.3 — Distributable CLI

> Engineering contract: [`../../AGENTS.md`](../../AGENTS.md)

Status: ✅ Complete

Depends on: Phase 4.2

---

## Objective

Evolve the repository-local `review:local` script into a stable distributable CLI surface without duplicating review logic or coupling the application layer to Node process APIs.

---

## Scope

### 1. Public CLI Contract

Define a stable executable contract for commands already proven by Phase 4.1:

```text
ai-reviewer review
ai-reviewer review --diff
ai-reviewer review --file <path>
ai-reviewer rules
ai-reviewer init
```

Preserve stable exit semantics:

- `0` — successful review / passing decision
- `1` — completed review with failing decision
- `2` — invalid usage, configuration, or operational failure

### 2. Package Surface

Prepare package metadata and exports required for distribution.

Requirements:

- one supported CLI entry point
- explicit package/bin exports
- no dependence on Vite/browser entry points
- no accidental publication of internal-only modules
- version output and help output are deterministic
- package build remains compatible with the repository's TypeScript/ESM stack

Any packaging dependency or build change requires explicit justification before implementation.

### 3. Process Adapter

Keep `process.argv`, stdout/stderr, exit-code assignment, and filesystem concerns in the CLI adapter.

The CLI must continue to delegate review execution to the shared application review use cases.

### 4. Machine-Readable Output

Add an explicit output-mode contract suitable for automation, initially:

```text
--format text
--format json
```

JSON output must use a versioned/stable schema derived from review-domain contracts rather than terminal strings.

### 5. Distribution Validation

Validate the packed artifact rather than only source execution.

Tests should cover:

- packaged executable invocation
- help/version
- config discovery
- file/diff review
- JSON output
- exit codes

---

## Non-Goals

- CI-provider-specific orchestration
- hosted API client
- automatic global install flows
- plugin marketplace
- self-update mechanism

---

## Acceptance Criteria

- [x] A documented executable entry point exists.
- [x] The packaged CLI invokes the same application review pipeline as local/GitHub paths.
- [x] Existing Phase 4.1 command semantics are preserved.
- [x] Text and JSON output modes are deterministic and tested.
- [x] Package exports do not expose accidental internal implementation surfaces.
- [x] Packed-artifact smoke tests execute successfully.
- [x] No browser/UI dependency is required to execute the CLI.
- [x] `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` pass.

## Implementation Evidence

- `package.json` exposes one `ai-reviewer` executable and restricts the packed surface to the Node CLI bundle, README, license, and package metadata.
- The process adapter injects the package version while `runCli()` continues to delegate review execution to the shared application `reviewFiles()` use case.
- Text output remains the default; JSON output uses a versioned schema derived from `ReviewResult` and omits non-deterministic duration data.
- Workspace traversal is sorted before analysis so text and JSON finding order does not depend on filesystem creation order.
- Packed-artifact tests build, pack, extract, and directly invoke the executable for help/version, configuration, file/diff review, JSON output, and exit codes `0`, `1`, and `2`.
- Validation performed on 2026-09-01: `npm run typecheck`, `npm run lint`, `npm test` (103 files, 739 tests), `npm run build`, `npm run test:package` (5 tests), and `npm run test:coverage`.
- The packed CLI is self-contained and about 11.2 MB unpacked; artifact-size optimization remains outside this phase.
