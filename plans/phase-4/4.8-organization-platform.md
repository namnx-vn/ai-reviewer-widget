# Phase 4.8 — Organization Platform & Policy Governance

> Engineering contract: [`../../AGENTS.md`](../../AGENTS.md)

Status: ⏳ Planned

Depends on: Phase 4.2, Phase 4.5, Phase 4.6

Recommended after: Phase 4.7

---

## Objective

Introduce organization-level review governance on top of the existing repository reviewer while preserving the same application review pipeline and deterministic policy semantics.

---

## Scope

### 1. Organization Policy Model

Define typed organization/repository policy contracts for:

- default review profile
- allowed/required rule families
- severity override boundaries
- quality-gate policy
- AI review mode policy
- repository-level override permissions
- policy/configuration version

Policy resolution must be deterministic and explainable.

### 2. Policy Precedence

Define explicit precedence, for example:

```text
built-in defaults
  ↓
organization policy
  ↓
repository configuration
  ↓
allowed invocation overrides
```

The final resolved configuration must record provenance so a user can understand why a rule/profile is active.

### 3. Repository Registration

Define application contracts for organization/repository identity and policy association.

Do not place GitHub installation/account logic in domain models; provider-specific identity mapping belongs to adapters.

### 4. Governance & Safety

Support organization controls such as:

- mandatory security gates
- forbidden rule disablement
- minimum severity/gate constraints
- allowed AI modes/endpoints through existing provider policy controls
- configuration validation/audit metadata

### 5. Historical Policy Context

Persist the effective policy/configuration snapshot with each review run so historical results remain explainable after organization policy changes.

### 6. Platform Adapter Integration

Organization policy must be resolved before invoking the existing review application use cases.

Do not introduce organization-specific analyzer variants or duplicate pipelines.

---

## Non-Goals

- billing/subscriptions
- full RBAC implementation unless separately planned
- GitHub Marketplace installation UX
- organization dashboard UI
- multi-tenant database vendor selection
- enterprise SSO

These may become later platform phases after the governance contracts are stable.

---

## Acceptance Criteria

- [ ] Organization and repository policy contracts are typed/versioned.
- [ ] Policy precedence is deterministic and independently testable.
- [ ] Effective configuration includes provenance for important policy decisions.
- [ ] Mandatory organization gates cannot be silently weakened by repository config.
- [ ] Provider-specific organization/repository identity stays in adapters.
- [ ] Review runs retain the effective policy/configuration snapshot needed for historical explanation.
- [ ] Organization policy feeds the existing application review pipeline rather than creating a new one.
- [ ] Tests cover precedence, forbidden overrides, repository policy resolution, provenance, and history integration.
- [ ] `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` pass.
