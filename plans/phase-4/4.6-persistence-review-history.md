# Phase 4.6 — Persistence & Review History

> Engineering contract: [`../../AGENTS.md`](../../AGENTS.md)

Status: ✅ Complete

Depends on: Phase 4.5

---

## Objective

Add persistence contracts for review runs and history without coupling the review domain or application use cases to a specific database technology.

---

## Scope

### 1. Persistent Run Model

Define an immutable review-run snapshot that can retain:

- run ID
- repository/source identity
- commit/ref metadata when available
- configuration/profile snapshot
- analyzer/AI mode metadata
- review result summary
- findings and warnings
- quality-gate result
- timestamps/duration metadata
- schema version

Persist enough information to explain a historical result without re-running the repository.

### 2. Persistence Ports

Define application ports for:

- create review run
- store completed result
- store terminal failure state where useful
- fetch run by ID
- list repository review history

Concrete storage remains outside application/domain boundaries.

### 3. Finding History

Provide a stable identity strategy for historical findings sufficient to support future comparisons such as:

```text
new
existing
resolved
```

Do not claim semantic equivalence across commits unless the matching policy can justify it deterministically.

### 4. Data Minimization

Avoid persisting full source content by default.

Persistence design must distinguish:

- source metadata
- finding excerpts/locations
- sanitized AI inputs if retention is ever needed
- secrets or sensitive source data that must not be stored

Reuse existing sanitization/security policy boundaries.

### 5. Storage Adapter

Only after the contracts are stable, add one minimal concrete adapter if implementation scope explicitly authorizes it.

Database/vendor selection is not part of this plan definition.

## Implemented Structure

```text
src/application/history/
  contracts.ts
  finding-history.ts
  snapshot.ts
  ports.ts
  service.ts
  in-memory.ts
  index.ts
  __tests__/
    history.test.ts
```

Implementation notes:

- `ReviewRunSnapshotV1` provides an explicit schema-versioned immutable persistence contract.
- Snapshots preserve repository/source identity, ref/commit metadata, resolved configuration, execution mode/AI provider metadata, timestamps, result summary, findings, warnings, and security quality-gate provenance.
- Full source content and raw AI inputs are intentionally absent from the persisted snapshot contract.
- `ReviewRunPersistencePort` defines create/update/get/list operations without importing a database client.
- `createReviewHistoryService()` owns lifecycle persistence and wraps storage failures in `ReviewHistoryPersistenceError`.
- Completion persistence failures retain the already-computed `ReviewResult` on the error so persistence failure cannot silently replace or corrupt the completed review decision.
- `createFindingIdentity()` uses deterministic rule/source/location/title/message identity rather than pretending to infer semantic equivalence across commits.
- `compareFindingHistory()` classifies findings as `new`, `existing`, or `resolved` using that explicit identity policy.
- `createInMemoryReviewRunPersistence()` is the minimal concrete adapter used to prove port behavior and history queries without selecting a production database vendor.
- Stored and returned snapshots are cloned to prevent caller mutation from changing persisted history state.

## Non-Goals

- choosing a production database in the plan itself
- analytics warehouse
- organization tenancy
- authentication
- long-term AI conversation memory
- storing entire repositories

---

## Acceptance Criteria

- [x] Review-run persistence contracts are typed and versioned.
- [x] Application code depends on persistence ports, not database clients.
- [x] Stored snapshots preserve configuration and result provenance needed for historical explanation.
- [x] Historical finding matching uses an explicit deterministic policy.
- [x] Source/secrets retention is minimized and tested.
- [x] Persistence failure behavior is explicit and does not silently corrupt a completed review decision.
- [x] Tests cover run lifecycle, serialization/versioning, history queries, and failure isolation.
- [x] `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` pass.
